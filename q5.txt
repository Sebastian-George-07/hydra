ARP Spoofing and Man-in-the-Middle (MITM) Demonstration


Aim
Understand how ARP spoofing can mislead devices on a local network, observe ARP changes, and explain mitigations.

Software Required
Two Linux VMs on a VirtualBox Host-only network (Kali attacker and your own victim VM); dsniff/arpspoof, tcpdump or Wireshark, curl, Python 3.

Safety / Scope
ARP spoofing is active network manipulation. Never use it on shared networks or devices you do not own. Do not attempt credential theft. If no isolated lab is available, complete the observation steps and explain the attack conceptually.

Procedure / Commands

A. Build the isolated network
1. Power off VMs. In VirtualBox > VM Settings > Network, select Host-only Adapter for each lab VM and choose the same Host-only network.
2. Do not use Bridged Adapter. Boot both VMs and run on each:
Phase 1: Kali Linux — Copy and paste

Step 1: Update Kali and install all required tools
sudo apt update && sudo apt install -y dsniff tcpdump wireshark curl python3

Step 2: Check IP addresses
ip -br addr

Step 3: Check the routing table
ip route

Step 4: Check ARP/neighbor entries
ip neigh

Phase 2: Victim Linux — Prepare the lab page
Run these commands on your victim VM, one at a time.

Step 5: Create the lab directory
mkdir -p ~/arp-lab

Step 6: Create the sample page
echo 'Lab demo page - no secrets here.' > ~/arp-lab/index.html

Step 7: Enter the directory
cd ~/arp-lab

Step 8: Start the HTTP server
python3 -m http.server 8080 --bind 0.0.0.0

Keep this terminal open.

Phase 3: Kali Linux — Test the connection

Step 9: Test connectivity
Replace VICTIM_IP with your victim VM's actual IP address.
ping -c 3 VICTIM_IP

Step 10: Request the sample page
curl http://VICTIM_IP:8080/

Expected output:
Lab demo page - no secrets here.

Step 11: Check neighbor entries
ip neigh

Phase 4: Capture ARP packets
Step 12: Open Wireshark
wireshark

Select the Host-only network interface and start capturing.

Step 13: Apply the display filter
arp

Step 14: Generate traffic
ping -c 3 VICTIM_IP

Step 15: Save the capture
Stop the capture and save it as arp-lab.pcapng.

Phase 5: Restore and verify

Step 16: Stop the HTTP server
Press Ctrl+C in the victim terminal.

Step 17: Refresh Kali's neighbor cache
sudo ip neigh flush all

Step 18: Check the neighbor table
ip neigh

Step 19: Verify your saved capture
Open the file manager and confirm that arp-lab.pcapng exists.

Expected Output
●	Before the test, ip neigh shows learned IP-to-MAC mappings.
●	tcpdump/Wireshark shows ARP packets and replies during the test.
●	The victim's gateway mapping may show a changed MAC while spoofing is running.
●	After stopping the tools and refreshing neighbor entries, normal connectivity should return.

Result
ARP spoofing was demonstrated only in an isolated, authorized virtual network; observations and mitigations were recorded.
