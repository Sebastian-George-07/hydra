Enable HTTPS on Apache2 Using a Self-Signed Certificate

Aim

Create a local X.509 certificate and private key, configure Apache TLS on port 443, and verify the HTTPS endpoint.

Software Required
•	Apache2 from Lab 2
•	OpenSSL
•	Firefox
•	curl

Procedure / Commands

1. Enable Apache's SSL module.

sudo a2enmod ssl

2. Create a directory for certificate files.

sudo install -d -m 700 /etc/apache2/ssl

3. Generate a self-signed certificate with SAN entries for localhost and 127.0.0.1.

sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout /etc/apache2/ssl/apache.key -out /etc/apache2/ssl/apache.crt -subj '/CN=localhost' -addext 'subjectAltName=DNS:localhost,IP:127.0.0.1'

4. Set restrictive permissions on the private key.

sudo chmod 600 /etc/apache2/ssl/apache.key
sudo chmod 644 /etc/apache2/ssl/apache.crt

5. Enable the default SSL virtual host.

sudo a2ensite default-ssl

6. Edit the SSL virtual host.

sudo nano /etc/apache2/sites-available/default-ssl.conf

7. In the `<VirtualHost _default_:443>` section, ensure these directives are set.

SSLEngine on
SSLCertificateFile /etc/apache2/ssl/apache.crt
SSLCertificateKeyFile /etc/apache2/ssl/apache.key

8. Test configuration and restart Apache.

sudo apache2ctl configtest
sudo systemctl restart apache2
sudo systemctl status apache2 --no-pager

9. Test HTTPS. `-k` bypasses trust checks for this local test only.

curl -k -I https://127.0.0.1
curl -k https://127.0.0.1

10. Inspect certificate details and TLS handshake.

sudo openssl x509 -in /etc/apache2/ssl/apache.crt -noout -subject -issuer -dates
sudo openssl s_client -connect 127.0.0.1:443 -servername localhost 

11. Open the HTTPS site.

https://127.0.0.1

Expected Output
•	`apache2ctl configtest` prints `Syntax OK`.
•	Apache listens on TCP 443; verify with `sudo ss -ltnp | grep ':443'`.
•	`curl -k` receives the page over HTTPS.
•	Firefox may show a warning because a self-signed certificate is not trusted by default.

Result

Apache2 serves the site over HTTPS with a self-signed certificate. The connection is encrypted, but the certificate is not publicly trusted.







1. What is HTTPS?
Answer: HTTPS is HTTP secured using TLS encryption.
2. What is the difference between HTTP and HTTPS?
Answer: HTTPS protects data in transit using TLS. HTTP does not provide that TLS protection.
3. What is SSL or TLS?
Answer: TLS is a protocol that provides encryption and integrity for network communication. SSL is its older predecessor.
4. What is a digital certificate?
Answer: It helps establish a website's identity and contains its public key and related information.
5. What is a self-signed certificate?
Answer: A certificate signed by its own creator rather than by a trusted certificate authority.
6. Is a self-signed certificate trusted automatically by browsers?
Answer: Usually not. Browsers normally show a warning unless the certificate is explicitly trusted.
7. Which port does HTTPS commonly use?
Answer: Port 443.
8. Why do we use a private key?
Answer: It is used in cryptographic operations and must be kept secret.
