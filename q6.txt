Web Application Vulnerability Assessment Using OWASP ZAP


Aim
Launch ZAP against the local WebGoat training app, review alerts, and document evidence and remediation.

Software Required
Kali Linux, OWASP ZAP, Docker, browser, local WebGoat from Lab 1.

Safety / Scope
Scan only local WebGoat or an explicitly authorized target. Active scans can change application state; use a disposable lab instance.

Procedure / Commands

A. Confirm WebGoat is running

$ docker ps
$ curl -I http://127.0.0.1:8080/WebGoat
If it does not respond, start the WebGoat container using the command from Lab 1. Keep it bound to localhost.

B. Install or launch ZAP

$ sudo apt update
$ sudo apt install -y zaproxy
Launch ZAP from the Applications menu or try:
$ zaproxy
If the package is unavailable, use the instructor-approved ZAP installation.

C. Set the target

1. Open ZAP and choose a temporary session unless instructed otherwise.
2. In Quick Start, select Manual Explore or Automated Scan.
3. Set the target to http://127.0.0.1:8080/WebGoat.
4. Confirm the target is localhost. Do not scan a public website or third-party IP.

D. Run a baseline assessment

Use ZAP Quick Start > Automated Scan only against local WebGoat. If the class requires passive-only testing, browse through ZAP and review passive alerts without active attacks.

E. Review alerts and save evidence

In the Alerts tab, record alert name, risk, affected URL, evidence, and recommended fix. An alert is not automatically proof of exploitability; inspect its evidence.
Check whether the optional report exists:
$ ls -l zap-baseline-report.html

Write each finding as: Finding; Risk; URL/evidence; Impact; Remediation; Retest. Never include secrets or session tokens.

Expected Output
●	ZAP opens and accepts the local WebGoat target.
●	The Sites tree and Alerts tab show activity/findings.
●	A report file is created if the selected scan method supports report generation.
●	Findings include risk ratings and remediation advice; results vary by version/configuration.

Result
ZAP was used to assess the local training app and findings were documented with risk, evidence, and remediation.







1. What is OWASP ZAP?
Answer: OWASP ZAP is a tool for testing web application security.
2. What is a vulnerability?
Answer: A weakness that could be exploited to affect a system's security.
3. What is vulnerability assessment?
Answer: The process of identifying, evaluating, and prioritizing security weaknesses.
4. What is passive scanning?
Answer: Examining observed requests and responses for potential security issues without deliberately attacking the target.
5. What is active scanning?
Answer: Sending test requests or payloads to identify vulnerabilities. It should only be done on authorized targets.
6. What is a ZAP alert?
Answer: A notification about a possible security issue found during testing.
7. Does every ZAP alert prove a vulnerability exists?
Answer: No. The evidence should be reviewed and the finding validated.
8. What should a vulnerability report contain?
Answer: The finding, risk level, affected URL, evidence, impact, and recommended fix.
